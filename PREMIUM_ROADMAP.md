# ALAY ART — план развития

Цель: премиальный сервис, а не обещание стоимости сайта. Каждая итерация завершается проверкой на мобильном, тестом бронирования и деплоем.

## 1. Надёжная основа — текущая итерация
- [x] Вернуть четыре категории из реальной БД.
- [x] Убрать внешние hotlink-ссылки у используемых фото: локальные WebP.
- [x] Сохранённый каталог при сбое сети; в резервном режиме только связь с отелем, без обещания актуальной цены/наличия.
- [x] Применить RLS и серверный расчёт цены в рабочей базе.
- [x] Проверить каталог и изображения в браузере, включая мобильный экран и сбой API.
- [ ] Подтвердить фактическое количество номеров каждой категории (технический лимит сейчас 1).
- [ ] Получить настоящую фотографию «Стандарт»: в текущей БД ему назначен орнамент. Декоративное изображение явно подписано.

## 2. Премиальная презентация — следующая итерация
- Единая дизайн-система: цвет, шрифты, отступы, аккуратная навигация на телефоне.
- Отдельная страница каждого типа номера: галерея, площадь, кровати, ванная, удобства, условия проживания.
- Фотографии без коллажей, реальные подписи, увеличение снимка, оптимизация для разных экранов.
- Проверенные отзывы с источниками вместо неподтверждённых маркетинговых утверждений.

## 3. Удобное бронирование
- Подтверждённые правила заезда/выезда, оплаты, отмены и размещения детей.
- Сохранение черновика брони до входа, ссылка на выбранные даты/номер.
- Email-подтверждение заявки и изменения статуса; повторная отправка и журнал доставки.
- При необходимости — гостевое бронирование с проверкой email, CAPTCHA и серверными лимитами.

## 4. Работа отеля
- Календарь загрузки, количество свободных физических номеров, блокировки на ремонт.
- Управление тарифами и фото без редактирования кода.
- Уведомления сотрудникам; разграничение ролей и журнал действий.
- Синхронизация с внешними каналами только после выбора поддерживаемого PMS/channel manager.

## 5. Рост и качество
- SEO-страницы RU/KY/EN, метаданные и реальные структурированные данные отеля.
- Аналитика воронки без передачи персональных данных гостей; мониторинг ошибок.
- Проверка доступности, Core Web Vitals и контроль работающих ссылок/изображений.
- Онлайн-оплата только через выбранного платёжного провайдера, не сбор карточных данных на сайте.

Для следующего шага нужны: фото «Стандарт», количество номеров по категориям, площадь/кровати, точные условия заезда и отмены. Ничего из этого не следует придумывать.

### Итерация 2 — страницы номеров (28.10.2026)
Выполнено: отдельные страницы по ID номера, полноразмерный просмотр имеющегося изображения, стоимость за выбранный срок, даты/гости в ссылке, кнопка «Поделиться», форма на мобильном перед описанием, продолжение заявки после входа по email, корректные состояния отсутствующего номера и ошибки API. Шапка проверена на ширине 320/390/768 px. Поддержаны RU/EN/KG.

Пока используется существующее изображение/коллаж из каталога; многоснимочная галерея, площадь, кровати и точные условия ждут подтверждённых данных владельца. Полный OAuth-возврат к черновику — отдельная задача. Следующий рекомендуемый этап: управление фото и параметрами номера в админке, чтобы владелец мог заполнить эти данные без правок кода.
